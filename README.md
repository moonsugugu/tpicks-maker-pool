# 티픽스 메이커 인력풀 조사

조사 페이지(GitHub Pages)입니다. 응답은 Apps Script 웹 앱으로 보내져 비공개 구글 스프레드시트의 '강사'·'가능 연수' 탭에 저장됩니다.

`map.html`은 등록된 강사를 시도별 지도로 보여 줍니다. 같은 웹 앱의 `?list=1`에서 성함·소속 교육청·근무지·자기소개·대분류·핵심 도구만 받아 오며, 전화번호와 이메일은 내보내지 않습니다. 조사 페이지에서 소속 교육청은 시도교육청 → 교육지원청 순서로 고릅니다. 지도는 이 글자(예전 응답은 근무지까지)로 시도·교육지원청을 찾고, 찾지 못하면 "지역 미상"에 넣습니다. 시도를 누르면 그 시도가 커지고 교육지원청별 점이 나옵니다.

`edu.js`(시도교육청 17곳·교육지원청 176곳과 점 위치)와 `map-geo.js`(시도·시군구 경계)는 `node tools/build-geo.js`로 만듭니다. 교육지원청이 바뀌면 그 스크립트의 목록을 고치고 다시 실행하세요.

`analysis.html`은 "주요 연수원 에듀테크·디지털 연수 분석" 페이지입니다. 연수 데이터가 파일 안에 들어 있습니다. 원본: 바탕 화면\티픽스랩스_교사연수데이터분석.html

2026-11-11 교총사제동행 공식 전체 과정표·AI 디지털 안내·과정 개요·목차에서 확인한 관련 과정 33개를 추가했습니다. 총 2,237개 연수 기록과 2,228개 추천 커리큘럼 항목입니다. 교총 자료의 출처 URL·공식 학점·확인일·공개 기수 일정·편집 분류는 `data/education-courses-2026-11-11.json`에 기록합니다. 공개된 현재 기수의 범위이며 연간 전체 일정 또는 전체 과정 수를 뜻하지 않습니다. 합본과 분할 과정은 공식 과정 ID별로 구분합니다. 추천 단계는 공식 난이도가 아닙니다.

출처 표시 순서는 교총사제동행 → 티처빌 → 비상 → 아이스크림 → 지식샘터 → 연구회 연수입니다. 연구회 연수 241개는 도구·주제·시간·분류를 유지하고 공개용 제목으로 바꿨습니다(`data/research-public-titles.json`). 목록·추천 커리큘럼에 같은 제목을 쓰며 날짜와 기관별 운영 기간은 연도까지 모두 비공개로 둡니다. 내부 원제목의 대조표나 시트 주소를 새 공개 자료에 넣지 않습니다.

분석 페이지 상단은 등록·지도 페이지와 같은 TPICKS LABS 로고, 보라색 격자 배경, 연두색 포인트와 연결 메뉴를 사용합니다. 바탕 화면 원본을 다시 복사하면 이 디자인과 숫자 표시 수정이 사라지므로, 현재 저장소 파일을 기준으로 수정하세요. 말풍선 표시·숨김은 차트 재그리기를 일으키지 않으며, SVG 라벨은 별도 사라짐 효과 없이 표시합니다.

분석 페이지 검증: `node tools/test-analysis.js`로 기존 자료의 보호 대상 필드, 교총 33개 과정·기수 일정, 출처 순서, 연구회 공개용 제목·연도, 스크립트 문법, 말풍선 표시 시 재그리기 방지, 탭·검색 갱신을 확인합니다. 보호 대상 필드의 변경 전 해시는 `tools/fixtures/analysis-data-integrity.json`에 있습니다.

협업 점수: 지도 첫 화면의 「시도를 골라 주세요」 아래에 「TOP 협업 점수」 버튼이 있습니다. 전국 강사를 점수 내림차순으로 보여 주며, 같은 점수는 공동 순위입니다. 0점과 미확인 실적은 순위 없이 아래에 표시합니다. 지역별 명단과 상세 소개에도 점수와 실적을 표시합니다.

응답 시트의 「협업 횟수」 탭에서 `연수 제작`·`도서 출판`·`원격 강의`·`대면 강의`를 입력합니다. 점수는 **(연수 제작 건수 + 도서 출판 권수) × 100 + 원격 강의 횟수 × 10 + 대면 강의 횟수 × 10**입니다. 화면에서는 연수 제작과 도서 출판을 「콘텐츠 제작」으로 묶고, 상세 소개에서는 각각의 실적도 보여 줍니다. `협업 점수` 열은 자동 계산합니다. 미확인 실적은 빈칸으로 두며, 0과 구분합니다. 이전 `협업 횟수`와 메모는 보관하고, 기존 총횟수를 유형별 실적으로 추정하지 않습니다. 기존 총횟수가 0인 행은 새로 추가한 유형도 0으로 초기화합니다.

Apps Script 원본은 `apps-script/Code.gs`입니다. 편집기에 반영한 뒤 `setupCollab`을 실행하면 기존 열과 입력값을 보존하면서 필요한 열과 새 강사를 추가합니다. 그 다음 「배포 → 배포 관리 → 수정 → 새 버전」으로 기존 웹 앱 주소를 유지해 배포합니다. 연락처는 공개 조회에 포함하지 않습니다. 데이터 원본은 사용자 지정 응답 시트 하나를 유지하며 별도 DB나 서버를 추가하지 않습니다.

검증: `node tools/test-collab.js`로 합산 점수, 공동 순위, 미확인 값, 시트 확장과 재실행, 공개 응답의 연락처 제외를 확인합니다.

등록 화면의 두 안내 링크는 본문 상단에 좌우로 넓게 배치하고, 작은 화면에서는 세로로 표시합니다. 등록 소요 시간은 제목 옆의 `(등록 약 5분)` 문구로 안내합니다.

제출 내용 수정·추가·삭제: 조사 페이지 맨 위 「이미 제출하셨나요?」에서 제출한 이메일로 6자리 인증 코드(10분 유효, 5번 틀리면 취소, 1분에 한 번)를 받아 확인하면 예전 내용을 불러옵니다. 수정 제출하면 같은 이메일의 예전 줄을 지우고 새 줄로 바꾸며, 삭제하면 「강사」·「가능 연수」에서 지웁니다(「협업 횟수」는 그대로). 인증 없이 이미 등록된 이메일로 제출하면 거절합니다. 메일은 웹 앱 소유 계정(MailApp, 하루 약 100통)으로 보냅니다.

강의 대상은 연수마다 고릅니다(유치원·초등·중등·고등 교사, 학생, 학부모, 관리자, 기타). 「가능 연수」 탭 마지막 「강의 대상」 열에 저장되고, 「강사」 탭 「강의 가능 대상」에는 그 선생님 연수 대상의 합이 들어갑니다. 「협업 횟수」 탭 열 순서는 Apps Script `orderCollab`으로 맞춥니다(협업 점수·연수 제작·도서 출판·원격 강의·대면 강의·메모·성함·이메일).

분석 페이지 첫 화면에는 연수 수 카운트업과 연수 하나를 점 하나로 그린 버블 지도가 있습니다(행성을 누르면 그 대분류 지도로 이동). 대분류 색(`--tpx-c1`~`c8`)은 TPICKS 보라·라임 계열입니다.

강사가 고른 정보만 공개: 등록 페이지 「강사풀 지도에 함께 공개할 정보」(대표 프로그램·대표 저서·연수 이력·SNS·커뮤니티·수상·이력)를 「강사」 탭 「공개 항목」 열에 저장하고, 공개 데이터(listPool_ → openExtra_)에는 고른 항목만 넣습니다. 핵심 도구 이름은 `tools.js`의 목록으로 통일합니다(새 도구는 거기에 한 줄 추가). 검사: `node tools/test-pool.js`.

메인 상단 「전문가 모집 공고 보기」는 `experts.html`로 연결합니다. 사용자가 제공한 「교사 숨고 페이지 v6-1.html」의 화면을 유지하고, `experts-connection.js`에서 기존 Apps Script 웹 앱에 연결합니다.

전문가 모집은 같은 비공개 응답 시트의 「모집 공고」·「모집 요청」·「모집 지원」 탭을 사용합니다. 저장이 필요한 영구 데이터이며 별도 DB·홈서버·공개 시트를 만들지 않습니다. 기존 「강사」·「가능 연수」 탭과 분리합니다. 초기 공고는 제공된 보훈교육 공고 하나이며 예시 공고는 저장하지 않습니다.

일반 공개 조회(`?recruit=1`)는 게시된 공고만 반환합니다. 모든 쓰기와 비공개 조회는 `action: recruit`의 작업별 API를 사용합니다. 6자리 이메일 인증(10분·5회 제한·재요청 1분 간격) 후 발급한 30분 토큰을 검사하며, 본인의 지원서와 담당 공고 지원자만 반환합니다. 운영자는 프로젝트 설정 → Script Properties의 `RECRUIT_ADMIN_EMAILS`에 이메일을 쉼표로 설정합니다. 초기 배포에서는 기존 웹 앱 소유 계정을 지정합니다. 계정 정보 자동 조회를 위한 추가 OAuth 권한은 요청하지 않습니다. 권한은 브라우저의 `#admin`이나 입력한 담당자 이메일을 믿지 않고 서버에서 확인합니다. 완료된 접수는 브라우저에 저장하지 않습니다. 인증 토큰과 계정별 입력 초안만 현재 탭의 sessionStorage에 두고 로그아웃할 때 지웁니다.

동시 쓰기는 Script Lock으로 직렬화하고 수정 버전이 다른 요청은 거절합니다. 승인·게시·지원서 접수·수정·철회·선발 상태·CSV 조회를 지원합니다. 일반 이용자에게 지원서·연락처·업체 담당자 이메일을 공개하지 않습니다. 지원자가 철회하면 해당 지원서를 삭제합니다. 운영자 「선발 종료 · 지원서 삭제」는 확인 후 해당 공고의 지원서만 삭제하고 공고를 비공개로 닫습니다. 공고의 단순 비공개 전환은 지원서를 삭제하지 않습니다.

배포 코드는 `node tools/build-apps-script.js <임시 파일 절대 경로>`로 `apps-script/Code.gs`와 `apps-script/Recruitment.gs`를 합칩니다. 기존 프로젝트의 Code.gs에 반영하고 운영자 이메일 속성을 설정한 다음 `setupRecruitment`를 한 번 실행한 뒤, 기존 웹 앱 배포를 새 버전으로 갱신합니다. `setupRecruitment`는 재실행해도 기존 공고·지원서를 덮어쓰지 않습니다. 검증 명령: `node tools/test-recruitment.js`, `node tools/test-pool.js`, `node tools/test-collab.js`. 실제 시트 연결 검사는 편집기에서 `testRecruitmentConnection`을 실행하며 검사로 생성한 요청 행만 정리합니다.

2026-11-11 운영 반영: 기존 웹 앱 주소의 버전 12에 배포했습니다. 운영 시트의 요청 저장·조회·수정 검사가 통과했고, 익명 공개 API·인증 없는 쓰기 거절·기존 강사풀 17건 응답 보존을 확인했습니다. 실제 메일 발송 검사는 수행하지 않았으며 인증 로직은 가짜 메일을 사용하는 자동·브라우저 검사로 확인했습니다.

로고: `tpicks-3d/`는 TPICKS 3D 로고 패키지에서 사이트 실행에 필요한 파일만 옮긴 것입니다(Three.js r180, MIT). 메인·전문가 모집 첫 화면은 `<tpicks-logo-3d>` 입체 로고를, 네 페이지 상단 로고는 `tpicks-3d/assets/tpicks-logo-traced.svg`를 씁니다. WebGL이 안 되면 `logo-fallback.webp`가 대신 보입니다.

카카오톡 공유: `window.TPICKS_KAKAO_JS_KEY`가 있으면 카카오 SDK로 보냅니다. 키가 없으면 안드로이드는 카카오톡 공유 화면(intent)을 바로 열고, 아이폰 등은 휴대폰 공유 메뉴를 엽니다. 공유 메뉴가 없는 기기에서는 공고 링크를 복사합니다.
